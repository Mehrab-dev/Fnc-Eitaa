# Fnc-Eitaa

## نصب مستقیم از گیت‌هاب

با Python 3.10 یا جدیدتر و Git نصب‌شده، در محیط مجازی خود اجرا کنید:

```sh
python -m pip install "git+https://github.com/Mehrab-dev/Fnc-Eitaa.git"
```

برای توسعه و تست تغییرات محلی، در ریشهٔ مخزن اجرا کنید:

```sh
python -m pip install -e .
python -m examples.account_login --live
```

نمونه‌های `examples` فقط از مخزن قابل اجرا هستند و همراه بسته نصب نمی‌شوند.
نصب مستقیم از گیت‌هاب، آخرین کد منتشرشده در مخزن را دریافت می‌کند؛ تغییرات محلی
تا پیش از push در این نصب قرار نمی‌گیرند.

## سایت مستندات فارسی و انگلیسی

راهنمای نصب، ورود و سشن، پیام‌ها، مدیا، رویدادها، صف SQLite و مرجع API در
[سایت مستندات](docs/index.html) آماده است. برای پیش‌نمایش، فقط پوشهٔ docs را سرو کنید:

```sh
python -m http.server 8765 --bind 127.0.0.1 --directory docs
```

سپس `http://127.0.0.1:8765` را باز کنید. سایت جست‌وجو، تغییر زبان، پوستهٔ روشن/تیره
و کپی کد دارد. مرجع متدها و مدل‌ها از کد پروژه تولید می‌شود:

```sh
python tools/build_docs.py
python tools/build_docs.py --check
```

برای انتشار با GitHub Pages، پوشهٔ `/docs` را به‌عنوان منبع انتخاب کنید.
جزئیات نگهداری و انتشار در [راهنمای سایت](docs/SITE.md) آمده است.

مسیر پیشنهادی مطالعه: [نصب و شروع سریع](docs/index.html#fa/installation) ←
[ورود و سشن](docs/index.html#fa/sessions) ← [مقصدها و گفتگوها](docs/index.html#fa/peers) ←
[پیام‌ها](docs/index.html#fa/messages). برای انتخاب تست بعدی،
[وضعیت تأییدها و محدودیت‌ها](docs/index.html#fa/validation) و
[عیب‌یابی](docs/index.html#fa/errors) را ببینید.

کتابخانهٔ async پایتون برای ارسال با توکن **ایتایار** و خواندن صفحات عمومی ایتا.
کلاینت اکانت شخصی `AccountClient` هم اضافه شده است؛ ورود واقعی با OTP و
اتصال مجدد بدون OTP توسط کاربر تأیید شده‌اند. رمز دوم و خطاهای سشن تست محلی
دارند و پذیرش زندهٔ جداگانه می‌خواهند.

شناخت پروتکل، هستهٔ ارتباط، ورود و سشن پیاده شده‌اند.
راهنمای اجرا در [گام ۳](docs/ACCOUNT_STEP_3.md) و جزئیات سازگاری پاسخ ورود در
[LOGIN_DECODING.md](docs/LOGIN_DECODING.md) است.
برای بررسی ورود روی حساب خودتان، شماره و کد را فقط در ترمینال وارد کنید:

```sh
python -m examples.account_login --live
```

پس از ورود موفق، همین دستور را دوباره اجرا کنید تا reconnect بدون OTP بررسی شود.
فایل `account.session` محرمانه است. بدون `--live` نمونه فقط توضیح آفلاین می‌دهد.

شمارهٔ موبایل ایران را راحت با `09…` (۱۱ رقم، مثل `09120000000`) وارد کنید؛
برنامه آن را خودکار به `+98…` تبدیل می‌کند. ارقام فارسی و عربی هم پذیرفته می‌شوند.
فرمت‌های `+98912…` و `0098912…` همچنان قابل استفاده‌اند. این رفتار هم در ورود
تعاملی و هم در `request_code()` یکسان است؛ شمارهٔ نمونه را با شمارهٔ خودتان جایگزین کنید.

### ورود هنگام شروع برنامه

`async with AccountClient(...)` ابتدا سشن را بررسی می‌کند. اگر سشن نباشد یا سرور
آن را صریحاً باطل اعلام کند، شماره و کد و رمز دوم احتمالی را در ترمینال می‌گیرد،
سشن را ذخیره می‌کند و سپس عملیات داخل بلوک اجرا می‌شود:

```python
import asyncio
from fnceitaa import AccountClient

async def main():
    async with AccountClient("account.session") as client:
        sent = await client.send_message("self", "تست ارسال پیام")
        print(sent.id)

asyncio.run(main())
```

سشن معتبر prompt ندارد. `await client.start()` هم همین مسیر را بدون context manager
ارائه می‌کند؛ در پایان `await client.disconnect()` را صدا بزنید. برای ورود برنامه‌ای
یا سرویس بدون ترمینال، `auto_login=False` بدهید و از `request_code`، `sign_in` و
`sign_in_password` استفاده کنید. `connect()` همچنان API سطح پایین و بدون prompt است.
شماره هنگام تایپ نمایش داده می‌شود و پس از ورود شمارهٔ معتبر، کد بدون تأیید yes/no
درخواست می‌شود. کد ورود و رمز دوم همچنان مخفی هستند و در فایل ذخیره نمی‌شوند.
در صورت `FLOOD_WAIT` هنگام ورود تعاملی، زمان انتظار نمایش داده می‌شود و برنامه
بدون traceback با وضعیت خروج ۱ خاتمه می‌یابد؛ پس از این زمان دوباره اجرا کنید.
در ورود برنامه‌ای با `auto_login=False`، خطا همچنان به فراخواننده برگردانده می‌شود.
خطای شبکه یا نتیجهٔ نامعلومِ ارسال، ورود دوباره و تکرار پیام را آغاز نمی‌کند.

## هویت مقصدها و گفتگوهای اکانت — گام ۴

با همان سشن ذخیره‌شده:

```sh
python -m examples.account_dialogs --live
python -m examples.account_dialogs --live --peer "@eitaa"
```

`resolve_peer` نام کاربری را به هویت واقعی مقصد تبدیل می‌کند؛ `get_dialogs`،
`iter_dialogs` و `get_dialogs_page` فهرست گفتگوها را با صفحه‌بندی می‌خوانند.
مدل `AccountPeer` نوع، شناسه و access hash مربوط به همان اکانت را نگه می‌دارد.
دریافت گفتگوها و resolve نام کاربری روی سشن واقعی در ۱۷ اکتبر ۲۰۲۶ بررسی شدند.
صفحه‌بندی چندصفحه‌ای هنوز پذیرش زنده می‌خواهد. نمونه کد، قواعد کش و محدودیت‌ها
در [راهنمای گام ۴](docs/ACCOUNT_STEP_4.md) هستند.

## پیام‌های اکانت — گام ۵

`AccountClient` اکنون `send_message` با ریپلای، `get_message`، `get_history`،
`iter_history` و `get_history_page` دارد. خواندن پیام و دو صفحهٔ تاریخچهٔ
کانال عمومی روی سشن واقعی بررسی شد؛ ارسال متن به خود، خواندن همان پیام، ریپلای
و خواندن تاریخچهٔ خود نیز با اجرای نمونه توسط کاربر تأیید شدند.

```sh
python -m examples.account_messages history --live --peer "@eitaa" --limit 5
python -m examples.account_messages send --live --peer self
```

دستور دوم پیش از ارسال، متن و مقصد را نشان می‌دهد و تأیید `yes` می‌خواهد.
ارسال با نتیجهٔ نامعلوم خودکار تکرار نمی‌شود. راهنمای تست ریپلای و مدیریت
random ID در [گام ۵](docs/ACCOUNT_STEP_5.md) است.

## رویدادهای اکانت — گام ۶

`AccountUpdates` رویدادهای پیام جدید، ویرایش و حذف را با polling دریافت می‌کند و
نقطهٔ ادامه را جدا از سشن ذخیره می‌کند:

```sh
python -m examples.account_updates --live --show-text
```

پس از `Updates ready`، در برنامهٔ ایتا یک پیام آزمایشی برای خودتان بفرستید.
خروجی `new` باید ظاهر شود؛ بعد ویرایش و حذف همان پیام را جداگانه تست کنید.
شروع تازه از وضعیت جاری است؛ اجرای دوباره از checkpoint ادامه می‌دهد.
تحویل حداقل یک بار است؛ شکاف غیرقابل بازیابی با خطا مشخص می‌شود.
اتصال فقط‌خواندنی و ذخیرهٔ وضعیت بررسی شده‌اند؛ دریافت زندهٔ سه رویداد برای پیام‌های
ذخیره‌شده و بازیابی پیام زمان خاموشی با `--replay-pts 1` را کاربر تأیید کرده است.
ادامهٔ معمول پس از توقف، بدون این گزینه، هنوز تأیید نشده است.
API، افزودن کانال، تست ادامه پس از قطع اتصال و محدودیت‌ها در [گام ۶](docs/ACCOUNT_STEP_6.md) هستند.

## عملیات پیام — گام ۷

`AccountClient` متدهای `edit_message`، `delete_messages`، `forward_message`،
`forward_messages` و `copy_message` دارد. نمونهٔ خط فرمان پیش از هر عملیات، مقصد و
شناسه‌ها را نشان می‌دهد و تأیید `yes` می‌گیرد. بدون `--live` فقط توضیح آفلاین می‌دهد:

```sh
python -m examples.account_actions edit
```

کاربر ویرایش، فوروارد، کپی و حذف محلی را همراه خواندن دوبارهٔ پیام در چت خود تأیید کرده است.
نمایش کپی بدون نویسنده و مقصدهای دیگر هنوز پذیرش جدا می‌خواهند.
درخواست نوشتن خودکار تکرار نمی‌شود و نتیجهٔ نامعلوم همراه شناسه‌های پیگیری برمی‌گردد.
قواعد حذف اشتراکی، کپی بدون نویسنده و دستورهای تست در [گام ۷](docs/ACCOUNT_STEP_7.md) هستند.

## مدیای اکانت — گام ۸

`AccountClient` متدهای `upload_file`، `send_file`، `send_photo`، `send_video`،
`send_voice`، `send_album` و `download_media` دارد. آپلود تکه‌ای است؛ دانلود پس از
تکمیل در مسیر انتخابی ذخیره می‌شود و SHA256 می‌دهد. اطلاعات مدیا و `grouped_id`
نیز در پیام‌ها قابل خواندن‌اند. کاربر ارسال و دانلود سند/عکس/ویس/ویدیو و آلبوم دو
عکس را در چت خود تأیید کرده است؛ فایل بزرگ، انواع دیگر آلبوم و مقصدهای دیگر باقی‌اند.

اولین تست با سشن موجود و فایل کوچک داخل پروژه:

```sh
python -m examples.account_media send --live --peer self --file examples/media_sample.txt
```

دستور پیش از آپلود، فایل و مقصد را نشان می‌دهد و `yes` می‌خواهد. بدون `--live`
درخواستی ارسال نمی‌شود. فرمت ویس، مشخصات ویدیو، آلبوم، دانلود و محدودیت‌های ادامهٔ
انتقال در [راهنمای گام ۸](docs/ACCOUNT_STEP_8.md) آمده‌اند. این API مربوط به اکانت
دارای سشن است؛ نمونهٔ `Client` با توکن Eitaayar در بخش بعد API جداگانه‌ای دارد.

## اطلاعات کامل و اعضا — گام ۹

`AccountClient` اکنون `get_full_user`، `get_full_group`، `get_full_channel` و
`get_chat_info` برای اطلاعات کامل مقصد دارد. تعداد اعضا با `get_member_count`،
فهرست صفحه‌بندی‌شده با `get_members_page`/`iter_members` و نقش یک شخص با
`get_member` قابل خواندن است، در حد دسترسی همان حساب.

```sh
python -m examples.account_profiles info --live --peer self
```

خواندن واقعی پروفایل خود و اطلاعات کانال عمومی ایتا موفق بوده است؛ اعضا و گروه‌های
دیگر هنوز پذیرش زنده می‌خواهند. شمارندهٔ ناموجود `None` است. جزئیات API، فیلترها و
محدودیت دسترسی در [راهنمای گام ۹](docs/ACCOUNT_STEP_9.md) آمده است.

## صف پایدار SQLite — گام ۱۰

`AccountClient.queue()` رویدادها و checkpoint را با هم در inbox ذخیره می‌کند و
درخواست‌های متن، ویرایش، حذف، فوروارد، کپی و مدیا را در outbox نگه می‌دارد.
ثبت در صف با ارسال فرق دارد؛ پس از اجرای مجدد برنامه، وضعیت و شناسه‌های عملیات
باقی می‌مانند. نتیجهٔ نامشخص خودکار دوباره ارسال نمی‌شود.

```sh
python -m examples.account_queue enqueue --live --peer self --key phase10-test-1
```

این دستور متن را فقط در صف ذخیره می‌کند. تست محلی و قطع فرایند انجام شده است؛
پذیرش زندهٔ صف باقی است. API، وضعیت‌ها، محدودیت‌ها و تست مرحله‌ای در
[راهنمای گام ۱۰](docs/ACCOUNT_STEP_10.md) آمده‌اند. پایگاه شامل محتوای پیام‌هاست و
رمزگذاری نشده؛ توکن/رمز/OTP در آن نگهداری نمی‌شود.

## ارسال متن و فایل

توکن را در متغیر محیطی `EITAAYAR_TOKEN` قرار دهید. ارسال نیازمند دسترسی توکن به مقصد است.

```python
import asyncio
import os
from fnceitaa import Client

async def main():
    async with Client(token=os.environ["EITAAYAR_TOKEN"]) as client:
        message = await client.send_message("@yourchannel", "سلام")
        print(message.id)
        await client.send_file("@yourchannel", "photo.jpg", caption="توضیح عکس")

asyncio.run(main())
```

`send_file` فایل محلی را به اندپوینت عمومی ارسال فایل می‌فرستد؛ نوع خروجی فعلاً
`DOCUMENT` است و ارسال تخصصی ویس یا آلبوم را پیاده نمی‌کند.

## خواندن اطلاعات عمومی

```python
async with Client() as client:
    info = await client.get_chat_info("@eitaa")
    message = await client.get_message("@eitaa", 123)
    if message is not None:
        print(message.text)
```

`get_info` نام سازگار برای `get_chat_info` است. این دو متد و `get_message`
نام کاربری عمومی می‌خواهند؛ شناسهٔ عددی چت خصوصی قابل خواندن نیست.

## دریافت پیام‌های عمومی

```python
from fnceitaa import Client, Router

router = Router()
client = Client(router=router)

@router.on_message()
async def on_message(message):
    print(message.id, message.text)

await client.run_polling(["eitaa"], interval=3)
```

نمونه‌های دارای `await` باید داخل تابع async اجرا شوند. Polling از آخرین پیام در
اولین بررسی شروع می‌شود و پیام‌های جدید حاضر در صفحه را به ترتیب شناسه تحویل می‌دهد.
پیام‌هایی که پیش از بررسی بعدی از پنجرهٔ صفحه خارج شوند ممکن است از دست بروند.
این روش رویداد ویرایش/حذف یا تاریخچهٔ اکانت خصوصی ارائه نمی‌کند.

خطای یک handler مانع اجرای بقیه نمی‌شود، اما پس از اجرای آن‌ها گزارش می‌شود.
در polling، پیام شکست‌خورده دوباره تلاش می‌شود؛ handlerها باید تکرار را تحمل کنند.
برای توقف از `client.stop_polling()` یا لغو task استفاده کنید.

## خطاها و محدودیت‌ها

- ارسال بدون توکن/اتصال، پاسخ ناموفق و شناسهٔ نامعتبر: `APIRequestError`.
- حذف پیام: `UnsupportedOperationError` تا پیاده‌سازی transport اکانت.
- `session_name` فعلاً برچسب است و فایل سشن تولید نمی‌کند.
- transport این نسخه مستقل است و به SDK ایتای دیگری وابسته نیست. درخواست‌های HTTP
  timeout اتصال/خواندن دارند. لغو task الزاماً thread درخواست را متوقف نمی‌کند.
  تغییر قالب HTML عمومی ممکن است به اصلاح parser نیاز داشته باشد.
- ارسال واقعی و سازگاری پاسخ سرور هنوز با توکن واقعی آزمایش نشده است.
- خواندن اطلاعات کانال عمومی، فهرست آخرین پیام‌ها و دریافت یک پیام با شناسه،
  در ۱۴ اکتبر ۲۰۲۶ روی کانال عمومی `eitaa` با موفقیت بررسی شد.
